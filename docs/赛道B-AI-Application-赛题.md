# 赛道 B：AI Application 方向（云原生智能体应用与场景创新）

## 题目

### 「云原生 Agent 实战：面向未来的 AI 应用设计与落地」

场景开放，不指定具体题目内容，但需要确保是有高价值的应用场景。

场景类型可参考但不限于以下示例表格：

| 场景类型举例 | 低价值 Demo（避免） | 高实际价值选题（鼓励） |
| --- | --- | --- |
| **研发/工程** | 自动写一段 HelloWorld 代码 | **线上故障处理**：发现监控告警后，自动分析日志、Trace、近期代码变更和配置差异，定位可能原因，生成修复方案，并联动工单/代码仓库/发布系统完成处置建议，形成"发现 → 分析 → 定位 → 修复 → 验证"的闭环 |
| **效率/学习** | 上传 PDF 然后生成摘要对话 | **科研问题研究**：围绕一个具体研究问题，自动检索多篇论文、提取实验数据和结论，对不同研究结果进行交叉验证，发现矛盾与证据缺口，并形成来源依据的研究结论 |
| **生产力/工作流** | 自动生成一份旅游攻略 | **复杂生活事务**：围绕真实目标完成信息搜集、比较、决策与执行，例如搬家、留学申请、家庭采购、行程安排等，能够综合预算、时间、个人偏好和外部实时信息，完成从"需求 → 方案 → 执行"的完整流程 |

> 方向关键词：**云原生架构** · **Agent 应用** · **场景创新**

## 主要考核点

1. **场景价值与痛点判断**：是否解决真实、明确且具有实际价值的问题，能否清晰说明目标用户、核心痛点以及使用 Agent 后带来的价值，而非"为了用 AI 而 AI"。
2. **云原生架构设计**：是否结合应用特点合理使用容器化（Docker/K8S）、微服务解耦、弹性伸缩与资源调度、分布式状态管理以及云上的其他基础设施等。需要提供相应的架构设计技术文档，并说明关键技术选型及设计逻辑。
3. **Agent 能力与链路质量**：任务拆解与规划的合理性、工具调用（Function Calling）的准确性、上下文/状态管理、多步骤 Task 的容错与异常恢复机制；如果有使用 Prompt、RAG 等技术，应体现其实际价值。
4. **工程完成度与 Demo 表现**：系统功能完整性、代码规范与可复现性（GitHub）、部署便捷性、异常处理及可观测性；演示视频能够清晰展示核心场景、Agent 执行过程与最终效果。
5. **成本与性能限定（考察工程化思维）**：对 API 调用成本、端到端延迟、资源消耗等进行合理预算与实际测算，并能够分析主要成本/性能瓶颈及优化方案。
